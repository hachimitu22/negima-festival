# AGENTS

## Markdown記述規則

- Markdownテーブルを作成または編集する場合は、各カラムの最長セルに合わせて半角スペースでパディングし、ソース上の列幅を揃えてください。
- 区切り行のハイフン数もカラム幅に合わせてください。
- 日本語などの全角文字は、表示幅2として扱ってください。

## ドキュメント運用方針

- `docs` に設計書を追加した場合は、`docs/.vitepress/config.js` の `themeConfig.sidebar` にも項目を追加し、サイドバーから辿れるようにしてください。

## 図表作成方針

- 小規模なフロー図や状態遷移図はMermaidで記述してください。
- Mermaidの`stateDiagram`系（`stateDiagram-v2`を含む）は使用せず、状態遷移図も`flowchart`で記述してください。
- マップのように規模が大きい図や、要素の順序・配置自体が意味を持つ図は `*.drawio.svg` で記述してください。
- Mermaidの自動配置で文字や要素が重なる場合、または意図した順序・配置を維持できない場合はdraw.ioを使用してください。

## テストケース作成方針

### 単体テストケース

- 単体と呼ばれる少量のコードを検証してください。
- テスト設計ではTest SuiteとTest Caseの親子関係を明示してください。
- caseは「前提」「入力」「操作」「期待結果」の共通フォーマットで記述してください。
- 異なる入力パターン、境界値、事前状態は個別caseとし、1つの振る舞いを証明するための連続操作は分割しないでください。

### 統合テストケース

- 明示的な依頼があるまで統合テストケースを作成しないでください。
