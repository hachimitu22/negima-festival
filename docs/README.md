# 文書索引

意図したゲーム仕様を正本とし、現在の実装状況は[実装状況](実装状況.md)で別管理する。

## 文書の分類

| 分類           | 読者           | 内容                                     | 正本とするもの     |
| -------------- | -------------- | ---------------------------------------- | ------------------ |
| ゲーム概要     | 開発者、企画者 | ゲームの目的と基本的な遊び方             | ゲーム全体の概要   |
| ユビキタス言語 | 開発者、企画者 | ゲーム内で使用する用語と概念             | 用語の意味         |
| 開発ルール     | 開発者、企画者 | 作業順と実装前ゲート                     | 実装前の作業条件   |
| 基本設計       | 開発者、企画者 | プレイヤーから見た挙動、ルール、状態遷移 | 意図したゲーム挙動 |
| 詳細設計       | 実装者         | 責務、API、データフロー、実装構造        | 実装上の設計       |
| テスト設計     | 実装者         | テスト方針、単体テストケース             | 検証方針と期待結果 |
| アイデア       | 企画者         | 未採用または検討中の案                   | 正式仕様ではない   |

## 文書状態

各ゲーム仕様には、仕様そのものの状態を記載する。
実装状況は[実装状況](実装状況.md)で別管理する。

- 仕様状態
  - `草案`: 内容を検討中
  - `確定`: 現時点の正本として扱う

仕様と実装が食い違う場合は仕様書を意図した挙動の正本とし、差異を実装状況ページまたは未決事項へ記録する。

## MahoPay収支の管理

- 具体的な獲得方法、使用方法、条件、ポイント数は`docs/.vitepress/data/mahoPayTransactions.data.js`だけに記述する。
- 収支に関係する仕様ページでは、中央データのIDを指定して`MahoPayTransactionTable`を表示する。
- 仕様ページの本文へ同じ条件やポイント数を手書きしない。
- [MahoPayポイント収支一覧](基本設計/ゲームシステム/MahoPayポイント収支一覧.md)は中央データから自動生成する。
- 中央データの形式、ID参照、仕様ページへのリンクはVitePressの文書ビルドで検証する。
- 中央データは文書上の正本とし、ゲームドメインからVitePress用データを参照しない。
- VitePress外でMarkdownだけを表示した場合、コンポーネントが生成する収支内容は展開されない。
- 項目数が増えた場合は中央データを分割しても、収支IDと表示コンポーネントの契約を維持する。
