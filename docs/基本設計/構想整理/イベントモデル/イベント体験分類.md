# イベント体験分類

## 文書情報

- 対象: イベントをプレイヤー体験の形式で分類する考え方

## 目的

麻帆良祭で起こるイベントを、プレイヤーが何を体験するかで整理する。

[イベント発生モデル](イベント発生モデル.md)は、イベントがいつ、なぜ発生するかを扱う。
この文書では、発生したイベントの中でプレイヤーが何をするか、どの程度のまとまりとして体験するかを扱う。

## 基本方針

イベントは、発生条件と体験分類を別軸で持てる。

たとえば、同じタスクでも定時に発生する場合、条件で発生する場合、突発的に発生する場合がある。
同じハプニングでも、軽いにぎやかしとして終わるものと、後続のエピソードへつながるものがある。

## 体験分類

### タスク

タスクは、短い目的を達成するイベントである。

主な体験は次の通り。

- 指定された場所へ行く。
- 見回りをする。
- 物を届ける。
- 状況を確認する。
- 誰かを探す。
- 短い期限内に目的を達成する。

教師仕事、配達、見回り、簡単な手伝いに向いている。
タスクは単体で完了してもよく、複数つながってエピソードの一部になってもよい。

### ハプニング

ハプニングは、突発的に起こる短い出来事である。

主な体験は次の通り。

- 急な事故や騒動に気づく。
- 迷子、落とし物、混雑などに遭遇する。
- 足場崩れや屋台トラブルなどに対応する。
- その場で助ける、避ける、見届ける。

ハプニングは、祭りの偶発性やわちゃわちゃ感を出すために使う。
すぐに終わるものもあれば、解決後にタスク、エピソード、派生イベントへつながるものもある。

### エピソード

エピソードは、人物、場所、出来事に関わるまとまった体験である。

主な体験は次の通り。

- 人物と会話する。
- 小さな悩みや目的に付き合う。
- 選択や短い行動で展開が変わる。
- その人物への理解や関係性が深まる。
- 複数の段階を進める。
- 複数の人物や場所に関わる。
- ループをまたいで知識や成果を積み上げる。

クラスメイト個別イベント、出し物に関する小話、特定人物との交流、原作再現、重要人物に関わる連続イベントに向いている。
エピソードの中に、タスクやハプニングを含めてもよい。
エピソードは、単発で完了するものと、複数回に分かれて進むものをどちらも含む。

イベント分類上は、シナリオをエピソードから分離しない。
シナリオという言葉は、3日目最終局面の固定シナリオなど、メイン進行上の大きな流れを表す場合に使う。

## 発生条件との組み合わせ

体験分類は、発生条件分類と組み合わせて使う。

| 発生条件       | 体験分類   | 例                                             |
| -------------- | ---------- | ---------------------------------------------- |
| 定時           | タスク     | 決まった時間に始まる見回りや手伝い             |
| ランダム突発   | ハプニング | 迷子、落とし物、屋台トラブル                   |
| 条件発生           | エピソード | 好感度や訪問済み情報で開く人物イベント         |
| 連続エピソード     | エピソード | 複数回に分かれて進む重要な出来事               |
| 定時               | エピソード | 特定時間だけ見られる出し物や人物との交流       |
| 条件発生           | タスク     | 教師仕事を一定数こなすと開く依頼               |

この表は代表例であり、分類を固定するものではない。
個別イベントごとに、発生条件と体験分類を組み合わせて整理する。

## 使い分け

- イベントがいつ出るかを考える場合は、発生条件分類を使う。
- プレイヤーが何をするかを考える場合は、体験分類を使う。
- イベント同士が盛り上がりや混雑へどう影響するかを考える場合は、[祭りイベント活性モデル](祭りイベント活性モデル.md)を使う。
- 失敗を次ループの手掛かりにする場合は、[失敗巻き戻しイベント](失敗巻き戻しイベント.md)を使う。
