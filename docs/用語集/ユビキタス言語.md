# ゲームイベント・Scene System設計方針：実装開始前の補足

## 1. InputModeとPlayerControlSystem

`PlayerControlSystem`は、フレーム後半で確定する制御結果ではなく、フレーム開始時点で確定している`InputMode`または操作コンテキストを参照する。

`InputMode`は少なくとも以下の状態を反映する。

```text
Gameplay
    通常のゲーム操作を受け付ける

Dialogue
    会話用入力だけを受け付ける

Rewind
    カシオペア・巻き戻し用入力だけを受け付ける

SceneTransition
    通常入力を受け付けない

Suspended
    メニューやモーダル表示などにより通常入力を受け付けない
```

例：

```js
const controlContext = {
  inputMode: "gameplay",
  playerCharacterId: "player",
  selectedTargetId: null,
};
```

`PlayerControlSystem`は`inputMode === "gameplay"`の場合だけ、通常のGameplay requestを発行する。

```js
class PlayerControlSystem {
  update(input, controlContext) {
    if (controlContext.inputMode !== "gameplay") {
      return;
    }

    // 通常操作をrequestへ変換する
  }
}
```

`InputMode`は`GameFlowSystem`が提供する。

Sceneは会話中、巻き戻し中などの条件を個別に判断せず、提供された`InputMode`をPlayerControlSystemへ渡す。

```js
const controlContext =
  gameFlowSystem.getControlContext();

playerControlSystem.update(
  input,
  controlContext,
);
```

`InputMode`と`frameControl`は別の目的を持つ。

```text
InputMode
    プレイヤー入力をどのSystemが解釈するか

frameControl
    当該フレームでゲームシミュレーションを進めるか
```

## 2. DialogueSystem.beginFrame()

`DialogueSystem.beginFrame()`は、当該フレームだけの一時状態を初期化する。

例：

* 当該フレーム中に会話を開始したか
* 当該フレーム中に会話を終了したか
* 当該フレームの入力を消費したか

ただし、進行中の`ConversationSession`は一時状態ではない。

`beginFrame()`によって進行中会話のシミュレーション停止状態を解除してはならない。

```js
class DialogueSystem {
  beginFrame() {
    this.startedConversationThisFrame = false;
    this.finishedConversationThisFrame = false;
  }

  getFrameControlState() {
    return {
      gameplaySimulationBlocked:
        this.activeSession !== null ||
        this.startedConversationThisFrame ||
        this.finishedConversationThisFrame,
    };
  }
}
```

以下の場合は必ずゲームシミュレーションを停止する。

```text
フレーム開始時点でConversationSessionが進行中
会話開始requestが当該フレームにAccepted
会話が当該フレームに終了
```

会話が終了した次のフレームから、停止状態を解除できる。

## 3. 同一フレーム中の複数request

EventSystemは同一フレーム中に複数のrequestを発行できる。

例：

```text
CharacterSystemへscripted move requestを発行
    ↓ Accepted

同一フレーム中にDialogueSystemへ
会話開始requestを発行
    ↓ Accepted

frameControlの最終判定
    ↓ gameplaySimulationEnabled = false
```

この場合、移動requestは受理済みだが、CharacterSystemの移動更新は実行されない。

移動はゲームシミュレーションが再開したフレーム以降に開始または継続する。

この挙動を初期仕様として許容する。

```text
requestの受付
    同一フレーム中に行われる

requestに基づく時間依存処理
    frameControlが許可したフレームだけ進行する
```

CharacterSystemは、受理済みrequestを停止中に失敗または完了扱いにしない。

停止中はqueueまたは開始待ち状態として保持する。

会話終了後に移動を再開してはならないイベントについては、EventInstanceが移動requestを明示的にキャンセルする。

## 4. request受付結果のデバッグ情報

各Systemはrequestの受付結果へ、必要に応じて以下の情報を含める。

```js
{
  acceptance: "accepted",
  requestId: "request-001",
  purpose: "scriptedEvent",
  blocking: true,
}
```

受付拒否の場合も`purpose`を含めてよい。

```js
{
  acceptance: "rejected",
  reason: "characterBusy",
  purpose: "scriptedEvent",
  blocking: true,
}
```

`purpose`と`blocking`は、Systemがrequest内容から決定した最終値を返す。

呼び出し側が指定した値をそのまま信用しない。

これらは主に以下に使用する。

* デバッグログ
* request追跡
* セーブ不可理由の確認
* 競合解決の確認
* EventInstance停止原因の確認

ゲームロジックは原則として、返却されたデバッグ情報だけに依存しない。

## 5. spatialStateVersion

位置状態の変更検知をCharacterSystemだけに限定しない。

各Systemが、自身の管理する空間状態のversionを提供できる構造にする。

```js
const spatialVersions = {
  characters:
    characterSystem.getSpatialStateVersion(),

  worldObjects:
    worldSystem.getSpatialStateVersion(),
};
```

LocationSystemは、前回処理時のversionと比較する。

```js
locationSystem.update({
  subjects: [
    ...characterSystem.getSpatialSubjects(),
    ...worldSystem.getSpatialSubjects(),
  ],

  spatialVersions,
});
```

いずれかのversionが変化した場合に、必要な進入、退出、訪問判定を行う。

初期段階で移動するWorldObjectが存在しない場合、WorldSystemのversionは固定値でもよい。

```js
worldSystem.getSpatialStateVersion();
// 0
```

将来の合成を想定し、単一のCharacterSystem用versionをScene全体のversionとして扱わない。

## 6. 更新順序の補足

初期更新順序を以下とする。

```text
1. 各SystemがbeginFrame()を実行する

2. InputSystemがInputSnapshotを生成する

3. GameFlowSystemがフレーム開始時点のInputModeを提供する

4. DialogueSystemが会話入力を処理する

5. PlayerControlSystemがInputModeに従って通常入力を処理する

6. NotificationBusが前フレームまでの通知を配信する

7. EventSystemがEventInstanceを進行しrequestを発行する

8. GameFlowSystemが各Systemの状態から
   frameControlを最終決定する

9. gameplaySimulationEnabledの場合のみ、
   ActorSystem、TimeSystem、CharacterSystemなどを更新する

10. WorldSystemがframeControlに従って更新する

11. LocationSystemが空間状態versionの変更を確認して更新する

12. 各Systemがsnapshot fragmentを生成する

13. SceneがSceneSnapshotを集約する
```

フレーム開始時の`InputMode`は、前フレームまでに確定している状態を表す。

EventSystemが当該フレーム後半に会話を開始した場合、そのフレーム前半にPlayerControlSystemが発行済みのrequestは原則として取り消さない。

ただし、会話開始によって競合するrequestがある場合は、各requestを管理するSystemの競合・キャンセル規則に従う。
